# Сетка усреднения (LONG) для фьючерсов MEXC

Одна страница: слева таблица USDT-фьючерсов, щелчок по паре — справа расчёт.

## Запуск

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

Открыть http://127.0.0.1:5000

## Модель

4 шага, маржа 1 / 2 / 3 / 4 USDT (сумма 10), коэффициент входа 0.85 — каждый
следующий вход ставится за 15% до текущей ликвидации. Плечо только целое.

```
шаг 1:      цена₁ = P1,  средняя₁ = P1
шаги 2..4:  цена_n = средняя_(n−1) − 0.85 × (средняя_(n−1) − ликв_(n−1))
монеты_n  = маржа_n × L / цена_n
средняя_n = L × Σмаржа_n / Σмонеты_n
ликв_n    = средняя_n × (1 − 1/L + MMR)
%пути_n   = (цена₁ − цена_n) / (цена₁ − цена₄) × 100
```

Режимы: цель по ликвидации 4-го шага (плечо подбирается численно и округляется)
либо плечо задано (ликвидация получается как результат).

## MMR

Ставка поддерживающей маржи берётся из тиров риска контракта и пересчитывается
на каждом шаге — позиция растёт и может перескочить в следующий тир.

Если биржа её не дала, расчёт не подставляет нуль молча: в шапке результата
стоит «MMR: нет данных», а рядом порог, до которого идеализированный расчёт
ещё безопасен (0.15 / L). Выше порога добор встаёт ниже реальной ликвидации —
именно это и ломало сетку на плечах выше ~50x.

Плечо, при котором MMR × L ≥ 1, невозможно физически — приложение возвращает
ошибку с предельным плечом, а не рисует таблицу.

Комиссия за открытие на цены не влияет (уменьшает и маржу, и объём на один
процент), фандинг биржа в расчётную ликвидацию тоже не включает — поэтому ни
то, ни другое в цепочку не заложено.

## Файлы

- `grid.py` — математика. Без сети и без зависимостей (scipy используется, если
  установлена, иначе встроенная бисекция).
- `mexc.py` — данные с биржи: список USDT-фьючерсов, цены, тиры MMR. Кэш на
  сутки в `.cache/`, при недоступности биржи отдаёт просроченный кэш.
- `app.py` — Flask.
- `test_grid.py` — 11 проверок: оба контрольных примера, инварианты, отсутствие
  молчаливого нуля в MMR, невозможное плечо, границы подбора, округление,
  нормализация символов, «вход n+1 выше ликвидации n» на плечах до 113x.

## Проверка

```
python test_grid.py          # математика
python mexc.py CAKE_USDT     # сырой JSON контракта + сверка имён полей
```

Второе печатает исходный ответ биржи и помечает поля, которых не нашлось, —
на случай, если MEXC снова переименует справочник.

Сверка с биржей: открыть форму ордера на MEXC с той же ценой и плечом и
сравнить Est. Liq. с ликвидацией первого шага. Допуск — доли процента.

## Что осталось непроверенным без живой биржи

- Количество округляется биржей вниз до целых контрактов (CAKE: 33.80 → 33) —
  модель считает дробными монетами. Даёт расхождение в последних знаках.
- Считается ли поддерживающая маржа от стоимости по цене входа или по цене
  ликвидации.
- Что именно входит в показанную биржей Margin (0.9672 против расчётных 0.9442
  на CAKE при Cost = 1 USDT).
