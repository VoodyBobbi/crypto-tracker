# Калькулятор сетки усреднения (LONG) для фьючерсов MEXC

Показывает, по каким ценам ставить 4 ордера на покупку, чтобы усредниться,
и где при этом окажется ликвидация.

## Запуск

**Двойной щелчок по `start.bat`.** Всё.

Первый раз он сам всё установит — это минута. Потом браузер откроется сам
на http://127.0.0.1:5000

Остановить: закрыть чёрное окно (или Ctrl+C в нём).

Нужен только Python с python.org. При установке отметить галочку
«Add python.exe to PATH».

<details>
<summary>Запуск через терминал, если нужно</summary>

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```
</details>

## На сервере (бесплатно, Render)

Приложение будет доступно по ссылке из любого места, с телефона тоже.

1. Отправить проект на GitHub (если ещё не там).
2. Зайти на [render.com](https://render.com) → войти через GitHub.
3. **New → Blueprint** → выбрать репозиторий `crypto-tracker` → **Apply**.
4. Подождать 3–5 минут, пока соберётся. Render покажет ссылку вида
   `https://setka-mexc.onrender.com`.

Всё остальное Render берёт из файла `render.yaml`: Docker, бесплатный тариф,
регион Сингапур. Дальше каждый `git push` обновляет сервер сам.

Что надо знать:

- **Засыпает.** Через 15 минут без посетителей сервер засыпает, первое
  открытие потом грузится около минуты. Пока страница открыта — не спит.
- **Регион Сингапур не менять.** MEXC советует доступ к своему API из Японии
  или Сингапура, из других мест их защита может не пускать.
- **Если над списком красное «Нет связи»** — MEXC не пускает этот сервер.
  Регион у готового сервиса на Render не меняется: поменяйте в `render.yaml`
  `singapore` на `frankfurt`, отправьте на GitHub, удалите сервис на Render
  и создайте Blueprint заново.
- Render может попросить привязать карту для проверки. На бесплатном тарифе
  деньги не списываются.
- Ссылку увидит любой, у кого она есть. Приложение только считает — ни ключей,
  ни доступа к аккаунту на бирже там нет.

<details>
<summary>Запустить в Docker у себя</summary>

```
docker build -t setka-mexc .
docker run -p 8000:8000 setka-mexc
```

Открыть http://127.0.0.1:8000
</details>

## Как пользоваться

1. Слева выбрать пару. Цена подставится сама.
2. Выбрать, что задаём: цель по ликвидации или плечо.
3. Вписать число, нажать «Посчитать».

Справа появится таблица из 4 строк. Это и есть 4 ордера: по каким ценам
покупать, на сколько долларов и сколько монет.

**Дальше всё обновляется само.** Цены в списке — каждые 3 секунды, таблица
пересчитывается под текущую цену. Над списком видно, живая ли связь:
«MEXC · обновлено 2 с назад» зелёным — всё хорошо. Красным «Нет связи» —
показаны последние известные цены, нужно проверить интернет.

Возле цены первого входа значок **● по рынку** — цена идёт за рынком. Если
вписать свою цену руками, таблица замрёт на ней. Вернуть — кнопка
«вернуть цену рынка».

## Что в таблице

| Колонка | Что значит |
|---|---|
| Шаг | Номер ордера. Первый — по рынку, остальные три — лимитки ниже |
| Вход | По какой цене ставить этот ордер |
| Вкладываю | Сколько долларов внести. Всегда 1, 2, 3, 4 — итого 10 |
| Количество | Сколько монет возьмёт биржа. Это число идёт в ордер |
| Ликвидация | Где закроет позицию, если цена дойдёт сюда после этого шага |
| % пути | Насколько глубоко просела цена относительно последнего шага |

Под суммой мелким шрифтом бывает «факт 0.85». Значит, биржа из внесённого
доллара реально задействует 85 центов: остальное не влезает в целое
количество контрактов. Точки входа посчитаны уже с учётом этого.

Сверху результата — плечо и строка про MMR. Если там красным
«MMR: нет данных», биржа не отдала ставку поддерживающей маржи по этой паре,
и ликвидация посчитана без её резерва. На большом плече это опасно — под
таблицей будет написано, до какого MMR такой расчёт ещё годится.

## Как работает

- 4 шага, суммы 1 / 2 / 3 / 4 USDT, всего 10.
- Следующий вход — когда сгорело 80% маржи. Считается от всей маржи, что уже
  внесена: после первого шага от 1 доллара, после второго от 3, после третьего
  от 6. Так вход всегда наступает раньше ликвидации.
- Плечо всегда целое.
- Ликвидация считается по формуле биржи, со ставкой поддерживающей маржи
  из тиров риска контракта. Тир пересчитывается на каждом шаге: позиция
  растёт и может перейти в следующий.
- Количество монет округляется вниз до целых контрактов, как это делает
  биржа, а из внесённой суммы сначала вычитается комиссия за открытие.

Комиссия и фандинг на точки входа не влияют, поэтому в цепочку не заложены —
биржа их в расчётную ликвидацию тоже не включает.

## Проверить, что всё работает

```
python test_grid.py
```

Должно вывести «ВСЕ ТЕСТЫ ПРОЙДЕНЫ» — 14 проверок математики.

```
python mexc.py <ПАРА>
```

Показывает, что именно биржа отдаёт по паре (вместо `<ПАРА>` подставить любую,
например `BTC_USDT`). Нужно, только если приложение начало ругаться на данные:
команда помечает поля, которых не нашлось.

Главная сверка: открыть на MEXC форму ордера с той же ценой и тем же плечом
и сравнить Est. Liq. с ликвидацией первого шага. Разница должна быть в долях
процента.

## Из чего состоит

| Файл | Зачем |
|---|---|
| `start.bat` | Запуск двойным щелчком |
| `Dockerfile`, `render.yaml` | Запуск на сервере |
| `app.py` | Сервер, отдаёт страницу |
| `grid.py` | Вся математика |
| `mexc.py` | Данные с биржи: список пар, цены, тиры риска |
| `test_grid.py` | Проверки |
| `templates/`, `static/` | Страница и оформление |

Цены с биржи — каждые 3 секунды. Ставки маржи и лимиты контрактов — раз в час,
хранятся в папке `.cache/`. Если биржа недоступна, берётся последнее известное.

## Чего приложение не делает

Не торгует, не отправляет ордера, не хранит ключи API. Только считает.
MEXC опрашивается публичными запросами, доступ к аккаунту не нужен.
