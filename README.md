# Калькулятор сетки усреднения для фьючерсов MEXC

Веб-калькулятор для LONG-позиций на фьючерсах MEXC. Выбираете пару и плечо (или желаемую цену ликвидации) — приложение показывает **4 ордера на покупку**: по каким ценам их ставить, сколько вкладывать и где после каждого шага окажется ликвидация.

> ⚠️ Приложение **только считает**. Оно не торгует, не отправляет ордера и не требует API-ключей. Данные берутся из публичного API MEXC.

---

## Возможности

- Живые цены с MEXC (обновление каждые 3 секунды) и автопересчёт сетки под текущую цену
- Расчёт ликвидации по формуле биржи с учётом тиров поддерживающей маржи (MMR)
- Учёт комиссии за открытие и округления до целых контрактов — как на бирже
- Два режима: задать **плечо** или **целевую цену ликвидации**
- Работает локально (Windows, Docker) или на бесплатном сервере Render

## Быстрый старт

### Windows — самый простой способ

1. Установите [Python](https://www.python.org/downloads/). При установке отметьте **«Add python.exe to PATH»**.
2. Дважды кликните по `start.bat`.

При первом запуске зависимости установятся автоматически (около минуты), затем откроется браузер на <http://127.0.0.1:5000>.
Чтобы остановить — закройте окно консоли или нажмите `Ctrl+C`.

### Через терминал

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

### Docker

```bash
docker build -t setka-mexc .
docker run -p 8000:8000 setka-mexc
```

Откройте <http://127.0.0.1:8000>.

## Как пользоваться

1. Слева выберите торговую пару — текущая цена подставится автоматически.
2. Выберите, что задаёте: **плечо** или **цель по ликвидации**.
3. Введите число и нажмите **«Посчитать»**.

Справа появится таблица из 4 строк — это и есть ваши 4 ордера.

**Индикатор связи** над списком пар:
- 🟢 «MEXC · обновлено N с назад» — данные свежие;
- 🔴 «Нет связи» — показаны последние известные цены, проверьте интернет.

**Цена входа.** Метка «● по рынку» означает, что первый вход следует за рынком. Если ввести цену вручную, расчёт зафиксируется на ней; вернуться к рыночной цене — кнопка «вернуть цену рынка».

### Что означают колонки

| Колонка        | Описание                                                          |
| -------------- | ----------------------------------------------------------------- |
| **Шаг**        | Номер ордера. Первый — по рынку, остальные три — лимитные ниже    |
| **Вход**       | Цена, по которой ставить ордер                                    |
| **Вкладываю**  | Сумма в USDT: 1, 2, 3, 4 (итого 10)                               |
| **Количество** | Сколько монет возьмёт биржа — это число вводится в ордер          |
| **Ликвидация** | Цена ликвидации, если рынок дойдёт до неё после этого шага        |
| **% пути**     | Насколько просела цена относительно предыдущего шага              |

**Подсказки в результате:**
- «факт 0.85» под суммой — биржа реально задействует только $0.85 из $1, остаток не помещается в целое число контрактов. Точки входа уже учитывают это.
- 🔴 «MMR: нет данных» — биржа не вернула ставку поддерживающей маржи, и ликвидация посчитана без неё. **На высоком плече это опасно** — под таблицей будет указано, до какого MMR расчёт остаётся корректным.

## Как устроен расчёт

- **4 шага** с суммами 1 / 2 / 3 / 4 USDT — всего 10 USDT.
- **Следующий вход** — в момент, когда сгорело 80% уже внесённой маржи (после 1-го шага — от $1, после 2-го — от $3, после 3-го — от $6). Поэтому очередной вход всегда наступает раньше ликвидации.
- **Плечо** — всегда целое число.
- **Ликвидация** — по формуле MEXC со ставкой MMR из тиров риска контракта. Тир пересчитывается на каждом шаге, так как позиция растёт.
- **Количество** округляется вниз до целых контрактов; комиссия за открытие вычитается из вносимой суммы.
- Комиссия и фандинг не влияют на точки входа и не входят в расчётную ликвидацию (биржа их тоже не учитывает).

**Кэширование:** цены — каждые 3 секунды; ставки маржи и лимиты контрактов — раз в час, хранятся в `.cache/`. Если биржа недоступна, используются последние сохранённые данные.

## Деплой на Render (бесплатно)

Позволяет открывать калькулятор по ссылке откуда угодно, в том числе с телефона.

1. Загрузите проект на GitHub.
2. Войдите на [render.com](https://render.com) через GitHub.
3. **New → Blueprint** → выберите репозиторий → **Apply**.
4. Через 3–5 минут Render выдаст ссылку вида `https://setka-mexc.onrender.com`.

Все настройки (Docker, бесплатный тариф, регион Singapore) берутся из `render.yaml`. Каждый `git push` обновляет сервер автоматически.

**Важно знать:**
- **Сервер засыпает** через 15 минут без посетителей — первое открытие после этого занимает около минуты.
- **Не меняйте регион Singapore без необходимости** — MEXC рекомендует доступ к API из Японии или Сингапура.
- **Если постоянно «Нет связи»** — MEXC блокирует сервер. Замените в `render.yaml` `singapore` на `frankfurt`, запушьте, удалите сервис на Render и создайте Blueprint заново (регион существующего сервиса изменить нельзя).
- Render может попросить привязать карту для проверки — на бесплатном тарифе деньги не списываются.
- Ссылка доступна всем, у кого она есть, но никаких ключей и доступа к аккаунту в приложении нет.

## Проверка

**Тесты математики** (14 проверок):

```bash
python test_grid.py
```

Ожидаемый результат: `ВСЕ ТЕСТЫ ПРОЙДЕНЫ`.

**Диагностика данных биржи** — если приложение ругается на данные:

```bash
python mexc.py BTC_USDT
```

Покажет, что MEXC отдаёт по паре, и отметит отсутствующие поля.

**Сверка с биржей:** откройте на MEXC форму ордера с той же ценой и плечом и сравните *Est. Liq.* с ликвидацией первого шага — расхождение должно быть в долях процента.

## Дисклеймер

Это инструмент для расчётов, а не финансовый совет. Торговля фьючерсами с плечом связана с высоким риском потери средств. Всегда сверяйте цифры с биржей перед выставлением ордеров.
